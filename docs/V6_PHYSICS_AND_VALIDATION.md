# BOARD//LAB 6 — Technical scope, verification and acceptance

BOARD//LAB 6 integrates a new general-purpose low-voltage electrical solver, schematic/PCB checking, a physically constrained software-rendered three-axis mechanical assembly, objective classroom grading, optional native ngspice verification, and measurement comparison.

## Student launch paths

- index.html: original PC/laptop diagnostics, procedural 3D workbench, PCB Studio and rework tutorials.
- digital-twin.html: original 5 V LED design-to-diagnose/repair workflow.
- engineering-lab.html: PCB factory, restricted virtual MCU, signal reflection, thermal rework and practice exams.
- circuit-lab.html: editable DC/nonlinear/transient electrical calculations, waveforms, schematic-to-PCB pin cross-probing, SPICE deck exports and reference dataset comparisons.
- assembly-3d.html: rotatable dimensional fictional laptop, selectable components/screws/cables, removal, reassembly and verification.

Serve the repository with Python or another local static server if the browser restricts local-file scripts. Optional classroom server: npm run serve.

## Circuit mathematics and independent verification

The simulation/mna-core.js engine uses modified nodal analysis with pivoted Gaussian elimination and Newton iteration. It solves independent V/I sources, resistors, exponential junction diodes and simplified square-law NMOS/PMOS. Transient C/L companions use fixed-step backward Euler. Cases have bounded node count, maximum components and 3,000 integration steps. Singular or nonconverging circuits explicitly error; the UI does not invent a meter reading.

Tests include analytical divider, 1 ms RC time constant, RL current, diode clamp, NMOS/PMOS switch, current source, timed pulses, invalid topology, and numeric bounds.

simulation/export-spice.js exports supported circuit compact models to an inspectable ngspice deck. Run npm run circuit:verify for a local MNA reference and export. Run npm run circuit:native to also invoke installed native ngspice. The separate .github/workflows/native-spice.yml workflow installs ngspice in GitHub Actions and stores reference artifacts. A native numerical pass is NOT physical model calibration.

## Schematic/ERC and PCB geometry

cad/erc-core.js derives training symbols and pins from PCB parts and compares pad numbers, declared electrical net names, reference designators, missing/unconnected pins, multiple outputs and conceptual unverified footprints. Board net checks cross-probe actual pads and copper from pcb-core.js. Manufacturer release is always locked; vendor-specific datasheets and actual KiCad ERC/DRC/DFM remain mandatory.

## 3D mechanics

mechanical/assembly-core.js defines a fictional 355 x 245 mm chassis with 7 removable assemblies, 23 fasteners, 5 detachable cables, lock states, battery isolation and thermal interface requirements. mechanical/mechanical-ui.js renders three-axis projected geometry with interactive yaw/elevation/zoom, exploded movement, physical-part picking and guided service steps. A full independent remove-reassemble-QA regression runs.

No OEM CAD, real torque requirements, elastoplastic strain, connector insertion force, hot-swap physics, battery hazard physics or manufacturing-grade collision system is implied. The torque and dimensions are synthetic training values only.

## Calibration data and reproducible acceptance

validation/golden-core.js compares user-supplied named measurements to calculated nodes. Its dataset format boardlab.golden.v1 requires circuit model, analysis type, probe data, named provenance and voltage tolerance. A report exposes failed points, maximum absolute error and RMSE. User-declared physical data is not treated as independently certified.

The included examples/v6/calibration/rc-synthetic-reference.json is intentionally generated by the solver itself. It tests numerical regression only, NOT real hardware accuracy. Run npm run calibration:check.

## Classroom scoring

classroom/grader-core.js verifies submitted circuit data and action sequences by rerunning actual simulation code. server.js stores scored submissions, not browser-asserted scores. An authenticated learner sees only own records, instructors see summary data. Scores are unproctored educational practice and are not professional credentials. Local server identity remains unsuitable for unreviewed public internet deployment.

## Engineering acceptance prerequisites still outstanding

1. Licensed OEM PCB and mechanical assets with pinouts, connector geometry, firmware and authorized service procedures.
2. Measured reference trainer boards and calibrated instrument captures over fault, load and temperature envelopes.
3. Supplier-validated symbols, footprints, manufacturer stackups and native fabrication CAD/ERC/DRC/DFM signoff.
4. Professional device vendor semiconductor models, high-speed channel/EMI/PI data and measured solder/rework materials.
5. Cloud production security, identity, backups, privacy policy, accessibility certification and accredited exams.
6. If generative tutoring is added: teacher-approved content, protected API service, privacy consent, safety grading and evaluation.

None of these can be genuinely validated simply by writing more browser code. Treat the completed simulation modules as reproducible education software and the above as external integration or qualification requirements.

## Reproducible checks

- npm test: all deterministic engine and interface regressions.
- npm run check: syntax plus all regression tests.
- npm run circuit:verify: compact electrical reference and restricted SPICE deck.
- npm run circuit:native: run local native ngspice if available.
- npm run calibration:check: synthetic reference comparator (self-check only).

Successful automated tests do not certify OEM hardware behavior, manufacturing release or actual technician safety.
